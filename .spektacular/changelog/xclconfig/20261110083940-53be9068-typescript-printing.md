# Printing, themes and the pretty logger for TypeScript

`xcl-lang` now prints configuration mistakes, entities and change summaries exactly as Go does, in plain text, terminal colour, HTML or SVG, styled by themes you extend in one line. A configuration mistake shows its source lines wherever it ends up: printed, on the console, left uncaught, or in pino and winston JSON logs, with no setup. Events can go to your own logger in one line, and a ready-made pretty logger shows each event and each created entity's configuration as it happens.

## What changed in this repo

- `src/highlight/`: `Kind`, `Token`, style strings and the colour palette, the frozen `defaultTheme`, `styleFor`, `validateTheme` (throwing the new `InvalidStyleError`), the five built-in formats, `css`, `forStream` and `loadVSCodeTheme`.
- `src/errors.ts`: `XclError` gained `tokens`, an own enumerable `report` accessor, the plain report in `stack`, and a custom inspect method that colours the report only when Node asks. `fromProto` makes `message` one line.
- `src/internal/wrap.ts`, `src/internal/render.ts`: detail wrapped as Go's go-wordwrap wraps it, counting code points.
- `src/print.ts`: `printError`, `formatError` and `printDiff`. `src/config.ts` gained `printEntity` and `entityTokens`, and `src/diff.ts` gained `tokens`, read in `src/internal/poll.ts`.
- `src/events.ts`, `src/internal/logbridge.ts`: `events.toLogger` and the rules of Go's logging bridge.
- `src/prettylog.ts`, `src/internal/prettyline.ts`, `src/internal/event-link.ts`: the pretty logger, its line layout, and each event's private link to the configuration that delivered it.
- `scripts/write-css.mjs` and `package.json`: the build writes `dist/xcl.css`, exported as `xcl-lang/xcl.css`. pino and winston are pinned dev dependencies, used only by tests.
- Tests: reference tests against xcl's published outputs, unit tests for every module, and real-engine tests. These cover reports, the uncaught route in a fresh process, JSON logs, the logger bridge, every pretty-logger scenario, and event-loop delay with the pretty logger on. The parity suite now compares every printing key with Go's.
- `README.md` and `PARITY.md` document printing, formats, themes, stylesheets, custom formats, logging and the pretty logger.

## Why

The TypeScript package had no printing support: a configuration mistake read as one line, output could not be styled, and watching an operation meant writing event handling by hand. Go and Python already had all of this, and the TypeScript package now matches them, held to the same reference outputs and parity fixtures.
